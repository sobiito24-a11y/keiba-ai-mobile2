# レースピックアップ・全頭比較UI（2026-10-23最終調整）

PC版・モバイル版に共通する通常予想画面の仕様。既存のAI候補を提示し、利用者が全頭の指数・状態・過去走・展開を比較して、購入馬と券種を決める。

この仕様は旧[印なし最終候補UI](final_candidate_ui.md)と前回の大型モバイルカードを通常画面について置き換える。最初に表示する比較対象は全頭一覧とし、上段の参考情報は利用者が必要なときに開く。旧仕様の「通常画面でA/B切替」「上段3項目を初期表示」「全頭一覧をスマホでは大型カード化」「過去走は前走→2走前→3走前」「全頭一覧には正式印を残す」は適用しない。旧版の仕様・検証結果はGit履歴で参照できる。

## 通常画面と予測データの保護

通常画面は現行Aの既存の正式スコア・正式順位・候補集合を使用する。A/B切替は通常の購入判断画面から外し、「研究Bの検証（通常予想とは別）」から従来の研究用比較画面を開く。

A・Bの計算式、固定係数、正式順位、内部印、参考✓の条件、保存済み予測値は変更しない。Bのコードや保存データを削除せず、`.keiba`の既存形式・A/B復元との互換性を維持する。研究Bの保存復元と、旧アーカイブからの事後再計算は従来どおり区別する。

休養、調教C/D、4角想定7番手以下、利用者の✓を理由とした新しい加点・除外・降格は行わない。オッズ取込、買い目研究、結果照合は既存機能を利用する。

## 画面構成と操作

表示順は、レース基本情報、レースピックアップ、レース展開予想、純能力の見える化、全頭予想・比較一覧、一覧の選択行直下に開く共通の馬別詳細、折りたたみの詳細分析・研究機能。

初回表示では、上段3項目と詳細分析・研究機能をすべて閉じ、全頭一覧を表示する。上段は独立したアコーディオンで、各タイトルと短い説明だけを表示する。閉じているピックアップの馬名・馬番・指数や、展開の有利馬を要約として先に表示しない。一方だけ開いても他のエリアの開閉に影響しない。

PCでは開いたピックアップを基本3列とする。全頭一覧はPC・スマホとも1頭1行の横比較テーブルを標準とし、自分の✓・枠番・馬番・馬名を左側に固定して指数部分を横スクロールする。全出走馬は縦方向に確認し、各馬の全項目をスマホの1画面幅へ押し込まない。スマホでは左右余白と固定列の幅を調整し、開いたピックアップと馬別詳細はコンパクトなカードとする。詳細の過去3走はPCで横並び、狭い画面では縦に読む。

### レースピックアップ

`core/final_candidate_selection.py`の既存選出を再利用する。正式Top5から最大5頭と既存の参考✓から最大1頭、重複を除いて最大6頭を馬番順に表示する。参考がなければ追加しない。単純なスコア上位6頭への置換や、表示のための新しい✓は作らない。

JRAは既存の正式順位1〜5位、NARは既存の`pure_ability_top5_group`を使う。NARの参考選出と保存済み選択の優先規則は`nar_check_selection.py`のままとする。既存判定が複数の参考馬を持つ場合でも、このエリアに出す参考は従来の比較UIと同じ最大1頭である。

カードには正式印、新しい候補内序列、本命・対抗等の呼称を出さない。上部は実際の枠色付き馬番、馬名・性齢・騎手、脚質・4角想定。中段はJRAの調教、前走間隔、斤量差、純能力指数を小さな比較枠に置き、今回斤量・騎手変更、最大3件の根拠がある短い特徴を続ける。下部に単勝・人気・提供元更新時刻を置く。情報を削らず余白と行高を抑え、最後の詳細操作は全頭一覧と同じ馬別詳細を開く。

### 展開と純能力

展開は既存の4角想定・脚質・出走頭数を読む。4角順位`r`、出走頭数`n`に対する`floor((r-1)*4/n)`で「逃げ・先団」「好位」「中団」「後方」の4帯に配置し、欠損・範囲外は位置未取得とする。脚質別の候補も示し、脚質と想定位置を同一視しない。

ペースは保存されたH/M/S等の値が一致する場合に表示し、不一致・欠損時は保留する。逃げ脚質の確認頭数、保存ペースに応じた注意、ピックアップ馬の位置を短文で示す。新たなペース推定や正式スコアへの加点はしない。

純能力は全頭を対象に、既存指数の高い順に横棒・数値・既存順位を示す。共通の線形尺度はゼロを含み、負数はゼロの反対側、欠損は未取得として扱う。差を誇張する馬ごとの尺度や新しい補正値は作らず、指数を勝率として表示しない。

### 全頭一覧と自分の✓

全頭一覧は馬番順を初期表示とし、全列で並び替えと絞り込みを操作できる。正式印・AI候補・参考候補・レースピックアップの行別マークは出さない。A正式スコアと正式順位は数値として比較できる。正式値がない参考馬に、参考式の値を正式スコアとして代用しない。

操作・基本情報は、自分の✓、枠番、馬番、馬名、性齢、騎手、単勝、人気。指数はA正式スコア・正式順位、純能力・距離・コースの指数とそれぞれの保存順位、3走平均、★最高指数。過去走は3走前・2走前・前走の指数と開催条件。脚質・4角想定・前走間隔・JRA調教・今回斤量・前走比・騎手変更、同競馬場／同距離／同競馬場同距離の保存範囲の実績、既存の判断材料も比較できる。

数値と順位は数値として昇順・降順、馬名・騎手などは文字列として並べ替える。未取得は昇順でも降順でも最後に置き、0へ変換しない。列見出しから並び替えを操作し、PCでは列の絞り込み入口も設ける。スマホでは共通の絞り込みエリアで対象列と条件を選び、常時並ぶ入力欄を増やさない。

数値は上下限、テキストは含む文字列、調教はA/B/C/D、手動✓はチェック済み／未チェックで絞り込める。取得済み／未取得だけの指定にも対応する。過去走の数値範囲はタイム指数を使い、開催条件の文字列検索と併用できる。異なる列の条件はANDで併用し、現在の条件をチップとして確認して個別解除または一括解除する。条件解除で手動✓は消さない。

過去走の順番は、一覧・共通詳細・既存の比較表示とも**3走前 → 2走前 → 前走 → 3走平均 → ★最高指数**とする。着順とタイム指数は別項目として扱う。

自分の✓は全出走馬に付け外しでき、頭数制限を設けない。全頭表示／自分の✓だけ表示、全選択解除に対応する。初回のレース表示は未選択で、AI候補を自動チェックしない。並び替えや詳細開閉で状態を失わない。

状態はJavaScriptの`Set`と、同一タブの`sessionStorage`にレースキー別で保持する。同じレースでのオッズ更新・再表示時にも、利用者の✓、並び順、列フィルター、アコーディオンの開閉、選択中の詳細、表のスクロール位置を保持する。他レースへ状態を混ぜない。保存領域が使えない場合も画面内の操作は継続する。✓はブラウザー内の比較操作であり、`.keiba`、予測結果、正式順位、AI候補、買い目データへ書き戻さない。✓の頭数によるBOX提案は作らない。

### 単勝・人気の表示

価格は既存`race_odds.py`のレース単位overlayを利用する。初回に新しい観測を取り込んでいない場合は単勝・人気を未取得とし、保存済み観測は明示的に選べる形で保持する。HTML取り込み後は単勝、取得できた場合だけの人気、取得できた場合だけの提供元価格更新時刻を表示する。HTMLを端末へ取り込んだ日時を、提供元の価格更新時刻として表示しない。

レースID・馬番・馬名照合、取消・除外、部分取得の扱いは既存処理に従う。部分観測へ切り替えた際は未取得馬へ古い価格を補完しない。単勝は観測値であり確定配当ではない。オッズによるA正式値や候補の再計算は行わない。

### 馬別詳細と既存分析

馬名・一覧行・ピックアップカードは、馬番で特定した同じ詳細処理を使う。通常は選択中の1頭だけを展開する。基本情報、A正式値と指数、過去3走、条件別実績、状態・変更、厩舎コメント原文、AIの解釈、プラス・注意材料を分ける。取得済みの数値は読みやすく示し、欠損指数は「未取得：距離・コース・★最高」のように小さくまとめる。0や架空の数値で埋めず、指数の定義も変えない。原文は省略せず、改行と空白を保持してHTMLエスケープする。原文がなければ未取得とする。

従来の12分析は「詳細分析」に残す。対象は、最終候補、展開・4角、純能力、コース、距離、調教・状態、★指数、☆指数、3走平均、今回＋／−、斤量／騎手、新AI総合（研究）。通常画面へ同じ大型比較表を重ねず、必要なときに折りたたみを開く。

### 前走間隔の日付検証

日数は「今回開催日 − 直近の実出走日」の暦日数とする。数値の着順、競走中止、失格は実出走として扱い、取消・除外は使わない。今回以降の日付は過去走に含めず、さらに新しい実出走の有無が不明な走があれば間隔も未取得とする。

保存日数と日付由来の日数が異なる場合は「未取得（保存間隔と日付が不一致）」とし、既存監査で不一致となった値も別の補完で復活させない。

「中N週」は月曜始まりの開催週間に挟まる週数。例えば日曜から3週後の日曜は21日・中2週。短い間隔は連闘または日数、40〜50日は約1ヶ月半、60〜119日は30.4375日／月で丸めた約Nヶ月、それ以外は日数で表示する。JRAとNARで定義を変えない。

### 条件別実績と初条件

開催日前と確認できる保存過去3走の範囲で、次の4種類の実出走数・3着以内回数・未確認数を表示する。

| 条件 | 必須の一致 | 表示例 |
| --- | --- | --- |
| 同会場・同馬場・同距離 | 会場＋芝ダート＋距離 | 東京ダ1600m：1戦1回3着以内（近3走の範囲） |
| 同会場・同馬場 | 会場＋芝ダート | 東京ダート：2戦1回3着以内（近3走の範囲） |
| 同馬場・同距離 | 芝ダート＋距離 | ダ1600m：1戦1回3着以内（近3走の範囲） |
| 同会場 | 会場 | 東京（芝・ダート通算）：3戦2回3着以内（近3走の範囲） |

「ダ」と「ダート」は同じ馬場として正規化する。芝とダートは最初の3条件で混ぜず、同会場通算のみ範囲を明記する。必須条件・着順が不足する場合は未取得・未確認とし、生涯成績や不適性に読み替えない。今回距離を過去の最高指数の距離から推定しない。

今回と前走の確定した距離・馬場の違いは変更情報にできる。ただし、過去3走にダート・芝・ブリンカー経験がないことから「初」を推定しない。現在の保存データには全キャリアや装着履歴の十分な証拠がなく、初ダート・初芝・初ブリンカー・再装着は表示しない。追加するには全過去走または信頼できる明示的な初条件情報、今回と過去の装着情報を取得し、取得元と判定根拠を表示用処理へ渡す必要がある。
