# 印なし最終候補の表示仕様

最終候補の比較UIだけを変更する。AIが提示した候補の指数・状態材料を比較し、購入馬・券種・買い目は利用者が決める。予測計算、A/Bの固定係数・正式スコア・正式順位・内部印、参考候補の元データ、`.keiba`形式、オッズ取込、既存の買い目・全頭分析・結果照合は変更しない。

## 候補の選出

`core/final_candidate_selection.py` は、選択中モデルの既存UI投影から**正式Top5を最大5頭＋既存の参考✓を最大1頭**取り出す。馬番を基準に重複を除き、正式候補を優先する。参考✓がなければ追加しない。旧画面の追加✔や `additional_reference` だけを根拠に新しい✓を作らない。

| 対象 | 正式Top5 | 参考候補と優先順 |
| --- | --- | --- |
| JRA・現行A | 保存された正式順位1〜5位 | Top5外の既存✓のみ。既存の正式順位、正式スコア降順、馬番の順で最大1頭 |
| NAR・現行A | 既存の `pure_ability_top5_group=True`。現在の正式Top5判定を再利用 | 既存✓のみ。保存済み選択を現在ルールの補完より優先し、その元の優先順を維持して最大1頭 |
| 研究B（JRA/NAR） | 正常に復元できたBの正式順位1〜5位 | BのTop5外に残るA由来の既存✓のみ。Bの正式候補との重複は表示しない |

NARの元ルールは `core/nar_check_selection.py` のまま。新規の参考✓は正式Top5外・純能力6〜8位・4角想定6番手以内が条件で、純能力順位、4角順位、騎手複勝率降順、元行順で選ばれる。元のレース全体上限（9頭以下は1頭、それ以外は2頭）も変更しない。

保存データでは `resolve_saved()` が明示的な `nar_check_selected`（Falseも含む）を優先し、なければ保存済み表示印✓、最後に既存ルールの補完を使う。凍結済み候補の絞込みは純能力順位・馬番を使用する。最終候補UIは、この既存判定を消したり再選出したりせず、表示上だけ参考を最大1頭にする。

Bの入力不足・保存不整合時は既存のAへの復帰を維持する。事後再計算されたBを、発走前に保存されたBとは扱わない。

## 並び順とレイアウト

- 初期表示は馬番順。最終候補の正式印・正式順位・最終評価スコアを表示しない。純能力等の指数・指数順位は比較材料として表示する。
- スコア順は選択中モデルの丸め前の正式スコア降順。同点は馬番順。並び替えは表示用インデックスだけに適用する。
- 正式スコアがない参考馬は末尾へ置き、「未取得」と表示する。ゼロや参考式の再計算値を正式スコアとして代用しない。Bに正式スコアが保存されている参考馬は、そのBの値を使う。
- PCは横比較テーブル。馬番と馬名・騎手の2列を左側に固定し、指数列を横スクロールできる。
- PCの長い判断材料は各2行のプレビューとし、馬名から全文を開く。モバイルではカード内に判断材料を表示する。
- モバイルは馬ごとのカード。重要指数、前走→2走前→3走前、調教・前走間隔・斤量・判断材料を縦に確認できる。馬名から詳細を開閉する。

実装の入口は `core/final_candidate_ui.py`、統合箇所は `core/game_race_ui.py`、操作と幅別表示は `core/game_ui_assets/race.js` / `race.css`。全頭一覧・既存分析画面の印は残す。

## 指標と材料の参照元

`core/final_candidate_metrics.py` は保存行と既存の表示用投影を読み取り、予測結果に書き戻さない。

| 表示項目 | 参照元・欠損時の扱い |
| --- | --- |
| 純能力・順位、距離・コース指数 | `game_race_ui.build_view()` の既存表示値・順位。距離・コースは保存行の対応指数も参照。新しい補正や再順位付けはしない |
| 前走・2走前・3走前 | `candidate_profile.facts()` の開催日前と日付確認できた過去走。ラベル順は必ず前走→2走前→3走前。タイム指数と着順を区別し、競馬場・芝ダート・距離・回り・日付を表示 |
| 3走平均 | 保存された `3走平均` / `近3走平均` / `recent3_avg` / `recent3_mean` を優先。JRAのみ既存の同義列 `平均指数` を許可。**NARの `平均指数` は5走平均なので転用しない** |
| 3走平均の表示補完 | 保存値がない場合だけ、日付確認済み3走の指数が全部あるときに表示用の算術平均を小数1桁で算出。`average_calculated` と参照元を保持し、画面に補完の説明を表示。予測・保存値へ反映しない |
| ★最高指数 | 保存された `★最高指数` / `★最高` / `star_max_index` / `_star_high`。一般の `最高指数` や新しい直近3走最大値へ置換しない。該当走・条件の保存情報に矛盾しない表示中の走だけに★を付ける。範囲外の最高走を直近3走へ移さない |
| 近走安定度 | 既存profileの指数ばらつき評価。「n/5（指数のばらつき）」とし、最高指数の★と区別 |
| 同距離・同コース好走 | `recent_condition_facts` の既存判定。保存過去3走の範囲を明示し、データ不足を不適性と扱わない |
| 騎手、調教、前走間隔、斤量、プラス・注意 | 既存の表示・監査済み材料を再利用。調教はJRAのみ。間隔の保存値と日付に矛盾があれば未取得。新しい除外・降格・スコア補正はしない |

欠損値は「―」「未取得」。現在レースの結果や未来の過去走を比較材料に取り込まない。

## 検証

各リポジトリのルートで、依存関係を導入したPythonを使う。

```bash
python -m pytest -q tests/test_final_candidate_selection.py tests/test_final_candidate_metrics.py tests/test_final_candidate_archive.py tests/test_game_ui_candidate_layout.py tests/test_game_ui_comparison.py
python -m pytest -q
```

候補数・重複・正式Top5保持、参考最大1頭、A/B切替、保存スナップショット不変、正式値・オッズ不変、欠損値、過去走と平均・最高指数の定義を確認する。ブラウザーではPC幅・モバイル幅の表示、スコア順切替、詳細開閉、固定列と横幅を確認する。

変更前の最新コードでの全テスト基準は、dashboardが1455成功・8失敗・2スキップ、mobileが1254成功・6失敗・5スキップ。以前の1432成功という結果とはコードの世代が異なる。最終結果は実行ログで比較し、既存失敗と新規失敗を区別する。

実データは利用者提供の `20261018_all.keiba`（74レース）内の秋華賞 `race_id=202608040711` も確認対象とした。A/Bとも最終候補は馬番順で `[1, 3, 4, 8, 9, 13]`。このファイルにBは保存されておらず、B表示は既存の `historical_recalculation`（事後再計算）経路である。保存済みBを復元した検証とは区別する。利用者の未公開ファイルはリポジトリへ追加しない。
