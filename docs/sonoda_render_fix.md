# 園田1R・2Rの表示エラー修正と性齢統合（2026-10-23）

作業ブランチは両版とも `fix/sonoda-render-inline-age`。開始時mainはPC `129f7ff0d98e10f00fd4520860de4b794da28e61`、モバイル `6b133002230332650e20f1aeded603ea0dfda72c`。

## 原因と修正

利用者提供の20261023アーカイブを各版の既存経路で復元し、次の2レースで同じ例外を再現した。

| レースID | 対象馬番 | 表示投影でNaNになる任意項目 |
| --- | --- | --- |
| 園田1R `202650102301` | 6 | `reference_selection.pure_rank` |
| 園田2R `202650102302` | 5 | `reference_selection.corner4_rank` |

例外は `ValueError: Out of range float values are not JSON compliant: nan`。
変更前の呼び出しは `render_game_prediction` → `paper_betting_ui.current_decision` → `paper_betting.build`（65行）→ `digest`（9行）→ `json.dumps(..., allow_nan=False)`。
元アーカイブの欠損nullがDataFrame復元時にfloat NaNになり、任意の参考選定メタデータに残った。馬券判断の入力全体を厳密JSONでハッシュ化する段階で停止するため、既に生成できていた比較表も描画に到達しなかった。

両レースとも10頭で、異常値は馬番順とは異なる表示投影の10番目にある。正常な園田3Rは7頭で、この投影に非有限値がない。添付35レースでは、変更前に失敗したのは上記2レースだけだった。正常レースの保存表にも未算出の正式スコア等は存在するが、通常の表示値はNoneへ整理されており、今回の停止原因は上記メタデータのNaNだった。

修正は `paper_betting.py` の入力ハッシュ用コピーに限定する。`_input_json()` がネストしたfloatのNaN／InfinityをJSONのnullに相当するNoneへ変換し、`build()` の `input_hash` 生成時だけ使用する。
元の馬データ、候補計算、返却する判断値を変更せず、0の補完や順位再計算をしない。`digest`・`freeze`・`verify`は厳密なまま維持するため、不正な固定記録や改ざんは引き続き拒否する。未対応の型も例外となり、広い例外捕捉は追加しない。

NaNを持つ対象2頭は既存の正式候補外で、強軸・妙味・相手候補に含まれない。入力ハッシュを生成できるようにしても候補を追加せず、欠損した正式スコアや順位は引き続き未取得と表示する。

## 性齢の固定セル統合

全頭一覧の馬名の右側に、小さな灰色文字の性齢を表示する。馬名の太字・font-size、固定4列の位置と幅は維持する。性齢の独立表示列を除き、性齢のソート・フィルターは残す。
性齢は折り返さず、長い馬名は固定幅内で折り返して、重なりや省略を防ぐ。未取得の性齢は「―」。指数・順位・上位3位記号のHTML、馬詳細カード、元のhorse payloadは変更しない。

PCの表幅は56px、スマホは44px減少した。馬名固定列はPC190px／スマホ118px、チェック操作の高さ44pxを維持する。
